# 0011. Tags name releases only and are permanent

> Amended by [0013](0013-release-workflow-tags.md): the release workflow, not the
> maintainer by hand, creates the tag. The other rules stand.

**Decision.** A tag is created only for a release (`v0.9.N`, or `v0.9.NrcM` for a
candidate), only by the maintainer, on the `main` merge commit of the release PR.
A pushed tag is never moved or deleted. Unreleased work is pinned by commit SHA,
not by a working tag. Full rules: [Tags and releases](../conventions/RELEASING.md).

**Why.** In November 2026 consumers pinned a working tag (`K9`) whose code reported
the previous version, and a pin that names neither a release nor a fixed commit
is hard to reason about. Permanent release tags make every pin reproducible.

**Follows.** `release.yml` refuses other tag names, commits not on `main`, and
tags without a changelog heading or a matching `__version__`. A tag ruleset on
`v*` can enforce maintainer-only creation and block updates and deletions.
